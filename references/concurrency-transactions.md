# 并发与事务

## 锁范围

锁状态保存在 Vault 外的本机运行目录，不进入知识正文。

- `work`：普通会话只锁一个当前问题笔记和其附件路径；同项目不同问题可以并行。
- `archive`：独占锁定检索层、资料层和归档清单内的待入文件；不阻止其他 AI 创建清单外的新待入问题。

所有路径规范化为 Vault 内相对路径，按排序顺序一次性申请。父路径锁与其全部子路径冲突。锁包含 owner UUID、模式、获取时间、最后心跳和到期时间。

默认租约 30 分钟。活跃写入每 5 分钟或每个长工具调用后运行：

```powershell
python scripts/vault_tool.py --config "<CONFIG_PATH>" heartbeat --owner "UUID"
```

过期锁可以回收，但如果关联事务未完成，不得仅凭过期抢占；先恢复事务。完成后：

```powershell
python scripts/vault_tool.py --config "<CONFIG_PATH>" release-lock --owner "UUID"
```

## 普通待入写入

`new-note --owner UUID` 原子创建或复用笔记并取得锁，返回取得锁时的 SHA-256。把拟写内容生成到临时输入文件后，通过 `safe-write` 提交预期哈希；不一致则拒绝覆盖。附件目录与笔记一起视为当前问题资源，但不要锁当天目录或整个项目。普通删除通过 `safe-delete` 移入 Vault 外7天隔离。

锁只约束遵守本 Skill 的 AI，不能阻止 Obsidian 或其他编辑器写入，因此哈希冲突检测不可省略。

## 归档事务

阶段固定为：

```text
PREPARED -> SNAPSHOT_CREATED -> MUTATING -> VALIDATED -> COMMITTED
                                      \-> ROLLED_BACK
```

- `PREPARED`：清单和路径确定，锁已取得。
- `SNAPSHOT_CREATED`：所有现有受影响文件已在 Vault 外建立快照和哈希清单。
- `MUTATING`：允许执行已记录的原子替换、移动和隔离。
- `VALIDATED`：结构、语义、链接、状态和哈希检查完成。
- `COMMITTED`：事务成功；归档清单中的旧待入路径已全部吸收或隔离，可释放锁并登记归档。
- `ROLLED_BACK`：按快照恢复，保留恢复记录供审计。

开始、扩展、推进和回滚都通过 `vault_tool.py` 命令完成。不得跳过阶段。修改现有文件前必须在事务中有其旧哈希和快照；新建目标必须在事务操作日志登记。

## 冲突处理

若实际 SHA-256 与事务预期不符：

1. 不覆盖发生变化的文件。
2. 将拟写内容保存在运行目录的事务冲突区。
3. 读取当前文件和拟写内容，判断能否合并。
4. Codex 已阅读全文并确认接受外部版本时，运行 `accept-external` 把它重新快照为新基线；需要合并时再执行新的原子操作。
5. 无法判断时停止该文件操作并报告用户。

不得自动使用“最后写入者胜出”。

## 恢复与清理

`health` 报告未完成事务和过期锁。下一次交互优先继续或回滚。回滚仅恢复事务实际改动的路径，并先检查当前哈希，避免覆盖事务之外的新修改。

已完成或已回滚事务的快照、隔离和冲突候选保留 7 天；`cleanup-runtime` 才能清除。未完成事务和未解决冲突不受7天清理影响。

│   └── _系统\

│   │   ├── 芯片与器件手册\
│   │   ├── 电路与硬件\
│   │   ├── 规格与需求\
│   │   ├── 日志与测试数据\

`00-检索层/_系统` 仅为旧版本兼容和必要的静态说明保留；正常运行状态、扫描报告、锁与事务不写入上两层。`90-待入层/_模板` 不属于某天的待归档内容。

锁、事务快照、删除隔离、冲突候选位于 Vault 外的本机运行目录，不属于三层知识正文。已完成恢复数据保留7天。

## 检索层职责

检索层回答三个问题：是否有相关资料、资料适用于什么范围、应该打开哪些文件或狭窄目录。它必须短、准、可验证，不复制资料层正文。

每个目录项使用以下格式：

```markdown
## STOP 模式退出后 USART2 不接收

- 关键词: USART2, STOP, 低功耗, 时钟恢复, 唤醒
- 项目/范围: 控制器项目；固件 V2.x；硬件 Rev.C
- 状态摘要: 事实 3；未验证 1；错误 1；过时 1
- 来源哈希: `sha256:...`
- 摘要: 唤醒后串口不接收的诊断、根因、修复和历史错误路径。
- 更新: 2026-08-12 17:45 +0000
- 资料: [[10-资料层/02-经验知识/故障与解决方案/STOP模式退出后USART2不接收]]
- 相关: [[低功耗恢复流程]]、[[USART调试检查表]]
```

每个目录项指定一个规范主资料及其来源哈希；其他资料放在“相关”链接中，或建立各自的目录项。这样来源哈希可以确定性检查，避免一个哈希含糊对应多个正文。

摘要只写足以路由的信息，不直接给出可能脱离上下文的操作指令。资料路径发生变化时，在同一归档事务内更新链接。

目录摘要必须准确且充分覆盖“资料是什么、适用于谁、能帮助判断什么、有哪些重要边界”，但不复制详细操作步骤。来源哈希变化时，该目录项进入待复核状态。资料层 Markdown 应至少被一个有效目录项链接；扫描报告把未覆盖文档列为孤立资料。

## 资料层职责

### 原始资料

保存用户提供的 PDF、图片、原理图、数据表、日志、测试数据和需求原件。原则：

- 保持原文件内容、文件名含义和版本信息，不为了格式统一改写原件。
- 同目录创建同名 `-资料说明.md`，登记来源、获取日期、版本/料号、适用范围、文件哈希和摘要。
- 摘要中的判断逐段使用知识状态；“文件来自用户”可以是事实，“资料内容是否适用于当前硬件”可能是未验证。
- 相同原件只保留一个规范副本，其他主题通过链接引用。

### 经验知识

保存从工作中提炼的项目知识、故障闭环、代码要点、调试方法、决策和个人偏好。按主要用途归入一个位置，用链接表达交叉关系，不因多个分类复制正文。

## 待入层职责

- 使用配置时区的本地时间日期目录和一问题一文档。
- 同一天同一问题持续更新同一文档。
- 允许初稿不完整，但现有知识性段落仍须标状态和记录日期。
- 附件放在当天目录内的 `附件/<笔记短名>/`。
- 归档成功后，已吸收内容可删除或移走；未解决项留在待入区并在归档记录中说明。
- 索引修订建议也存入当天目录，记录旧索引和来源哈希，归档时才写入检索层。

## 命名

- Markdown 文件名使用能直接表达主题的中文短标题，避免“记录1”“新文档”等名称。
- Windows 文件名不得包含 `< > : " / \\ | ? *`。
- 同名主题用项目、器件或版本消歧，例如 `项目A-低功耗唤醒失败.md`。
- 原始资料尽量保留发布方文件名，并在资料说明中补充可读标题。

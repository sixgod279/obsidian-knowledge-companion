# Obsidian Knowledge Companion

一个可直接安装的 Codex Skill：使用「检索层 → 资料层 → 待入层」管理 Obsidian 工程知识，支持自动检索、记录、本地事务归档。

仓库包含技能、工具与公开默认配置，不包含实际知识库或账号凭据。技能代码仓库可以公开；知识库资料仅存放在独立本地目录。

注：安装Obsidian能使你直观的查看资料库，若不安装，也不影响智能体使用本skill。

## 功能简述

这个 Skill 帮助 AI 将日常工程工作中有价值的信息沉淀到本地 Obsidian 知识库，并在后续处理相关问题时检索已有经验。它提供工作流程和本地辅助脚本，由 AI 完成资料理解、语义整理与判断。

- **分层检索**：先查简洁的主题索引，再读取相关资料，减少重复翻阅和无关信息。
- **日常记录**：按配置捕获问题现象、排查过程、验证结果、项目决策和个人偏好；新内容先进入待入层。
- **知识归档**：手动或在配置时间后的交互中触发整理，检查重复与冲突，并同步更新本地资料和索引。
- **证据与状态管理**：区分事实、未验证、错误和过时知识，保留适用范围与证据，避免把旧结论直接套用到新问题。
- **原始资料保留**：保存文档、图片、原理图和日志等原件，通过旁注记录来源与解释；解析能力取决于 AI 当前可用工具。
- **本地写入保护**：通过文件锁、事务快照和恢复流程降低并发修改风险；不包含知识库上传或远端同步功能。

## 适用场景

| 场景 | 可以怎样使用 |
|---|---|
| 固件、硬件和软件调试 | 保存故障现象、排查步骤与实测结论，下次遇到类似问题时查找已有经验。 |
| 长期项目维护 | 按项目和版本积累设计决策、限制条件与变更原因，帮助重新进入项目时恢复背景。 |
| 技术资料积累 | 将手册、原理图、测试日志等原始资料与分析笔记关联，方便按主题定位。 |
| 跨会话延续工作 | 将值得保留的结论写入本地文件，在后续会话调用技能时检索，而不依赖单次聊天上下文。 |
| 个人工作方式沉淀 | 按配置记录编码习惯、验证要求与协作偏好，供后续相关任务参考。 |
| 整理零散工程笔记 | 将待入内容归档到正式资料层，复核重复、冲突和过时信息，并维护检索入口。 |

适合希望长期维护本地工程知识、并愿意保留证据与验证状态的个人使用。它不提供后台定时服务或完整聊天历史备份；知识检索、记录和归档需要 AI 在会话中调用技能执行。

## 让 AI 直接安装

把本仓库链接或解压目录交给有本机文件与终端访问能力的 AI，并发送：

> 阅读这个仓库的 README.md，按其中的 AI 安装流程直接完成安装、默认配置落地、知识库初始化和验收。保留已有技能、配置和知识库。仅在本地工作，不配置知识库远端或上传资料。完成后告诉我技能目录、配置路径、知识库路径和验证结果。

仅能聊天、不能操作本机的 AI 无法执行安装；可由用户执行下列命令。

## 默认行为

默认值统一来自 `assets/config.example.json`，用户无需手工填写 JSON 即可使用。

| 项目 | 默认值 |
|---|---|
| 知识库 | `~/ObsidianKnowledge`，`~` 为当前用户主目录 |
| 本地配置 | `~/.config/obsidian-knowledge-companion/config.json` |
| 时区 | `Asia/Shanghai`（北京时间） |
| 自动归档 | 开启，每日 17:30 后适用交互触发 |
| 自动检索 / 工程工作记录 / 个人偏好记录 | 开启 |
| 默认展示知识来源 | 关闭；用户要求时展示 |

时间检查依赖 AI 调用技能，不安装后台服务，不会在关闭 Codex 时自动运行。技能自动选择也不能保证每轮都会被调用；需要确定执行时，请显式使用 `$obsidian-knowledge-companion`。

## AI 安装流程（按顺序执行）

### 1. 确认来源和运行环境

- 以用户提供的仓库链接或目录为来源，不猜测 GitHub 用户名、仓库名或旧电脑路径。
- 检查 Python 3.10+，使用实际可用的 `python`、`python3` 或 Windows `py -3`；后续命令始终使用同一个解释器。Obsidian 是可选的笔记界面，不是脚本运行依赖。
- 缺少 Python 时，Windows 可检查 `winget` 并安装 `Python.Python.3.12`；macOS 可在已有 Homebrew 时执行 `brew install python`；Linux 使用其包管理器安装 `python3` 和 `python3-venv`。不要假设这些包管理器都存在。权限或联网阻止安装时，说明实际阻碍，不报告安装成功。
- 用所选解释器执行 `python -c "from zoneinfo import ZoneInfo; print(ZoneInfo('Asia/Shanghai'))"`。时区数据缺失时执行 `python -m pip install tzdata`。若系统限制 pip 安装，在用户目录创建虚拟环境，例如 `python -m venv ~/.local/share/obsidian-knowledge-companion/venv`，并用其中的解释器安装 `tzdata` 和执行后续命令。不要用 `--break-system-packages`。

### 2. 安装到技能目录

默认安装位置：`~/.agents/skills/obsidian-knowledge-companion`。遵循 [Codex 官方技能目录说明](https://developers.openai.com/codex/skills)。

1. 用户给的是 Git URL 时，克隆到上述尚不存在的目录；用户给的是 ZIP 或本地目录时，完整复制技能文件到该目录，保证 `SKILL.md` 直接位于目录根部，避免多套一层同名目录。
2. 安装前检查目标目录，以及 `~/.codex/skills/obsidian-knowledge-companion` 是否已有同名技能。已有任一版本时先报告并保留，不自动覆盖，也不安装第二份同名技能。可先在用户提供的源码目录完成验证；升级需使用用户明确指定的升级范围。
3. 不把个人配置、Vault 或凭据放进技能仓库。不修改其他技能。
4. 后续命令在本技能根目录运行；如果使用绝对脚本路径，则无需切换工作目录。

### 3. 一次命令落地配置和知识库

在技能根目录执行：

```powershell
python scripts/setup.py
```

安装脚本会：

- 首次创建独立本地配置，解析当前用户主目录，写入默认值；
- 已有配置时保留原文件，不覆盖用户选择；
- 初始化三层目录、索引与模板；已有资料不覆盖；
- 依次执行 `show-config`、`init`、`health`、`check-archive`，输出 JSON 验收报告；
- 只检查归档是否到期，不在安装阶段自动归档。

若用户明确指定其他知识库，首次安装可执行：

```powershell
python scripts/setup.py --vault "D:/MyKnowledge"
```

若用户选择已有知识库，应直接使用该路径。如有旧知识库，使用已有本地副本或用户手动迁移后的目录。技能文件不包含旧知识库数据。

自定义配置文件用 `--config` 指定。标准位置的配置会自动发现，无需设置环境变量。若设置了 `OBSIDIAN_COMPANION_CONFIG` 或 `OBSIDIAN_VAULT`，安装前先检查其值并在结果中说明；它们可能选择已有配置或覆盖 Vault 路径，不要静默修改用户环境。

### 4. 验收并让 Codex 识别

```powershell
python scripts/vault_tool.py show-config
python scripts/vault_tool.py health
python scripts/vault_tool.py check-archive
```

自定义配置不在标准位置时，每条命令都加 `--config "实际配置路径"`，或按用户选择设置 `OBSIDIAN_COMPANION_CONFIG`；setup 不会自动设置持久环境变量。

验收条件：命令成功退出；配置符合用户指定值或上述默认值；三个知识库目录已创建；`health.ok` 为 true 且没有未完成事务。本地使用不需要 Git 或任何远端账号。

Codex 会发现技能；如果没有出现，重启应用并新建会话。验证调用：

> 使用 $obsidian-knowledge-companion，检查我的配置和知识库状态。

随后可以让 AI 记录一条用户提供的真实内容，再检索它。注意新记录先进入待入层，归档后才进入正式检索层；不要为安装测试伪造工程事实或向正式知识库写入测试垃圾。

最终报告实际 Python 路径、技能目录、配置路径、Vault 路径、各项验证结果。不能只给操作建议而不执行已获授权的本地安装步骤。

## 配置调整与日常使用

修改独立本地 JSON 即可，不必修改技能文件。配置字段及优先级见 [references/configuration.md](references/configuration.md)。本版本不包含知识库上传或远端同步功能。

常用请求：

- “查找以前处理过的串口接收故障。”
- “把本次调试结论记录到知识库。”
- “归档当前待入内容。”
- “这轮不要查知识库。”

用 Obsidian 的“打开文件夹作为仓库”选择实际 Vault 路径，即可查看笔记。

## 分享与更新

公开上传整个技能目录前，确认没有带入本地配置、知识库、运行快照和凭据。`.gitignore` 只排除常见本地产物，不能代替检查；`assets/config.example.json` 是应提交的默认配置。

更新技能时保留独立本地配置及 Vault；`setup.py` 重跑不会覆盖它们。切换时区或迁移资料前先检查未完成事务。

旧版本升级：既有配置中的同步字段会被忽略，无需为本地运行删除配置文件。旧同步状态不再读取，也不会触发重试；本版本不会修改已有 Vault 的 Git 元数据。
